# 客户侧部署与模型配置指南

> 适用场景：客户在自己机房 / 私有云里部署 LuoSA，统一对接自建的 vLLM（或任意 OpenAI 兼容 API）。目标效果——**平台管理员在 Web 端配一次模型，所有员工立即可用**，普通员工看不到任何模型配置入口。

## 1. 部署架构总览

```
┌──────────────────────────────────────────────────────┐
│  客户内网 / 私有云                                    │
│                                                      │
│   ┌────────────┐    ┌─────────────────────────┐     │
│   │ vLLM 服务  │    │ LuoSA 平台              │     │
│   │ (端口 8000)│◄──┤  ├─ 后端 (Go)            │     │
│   └────────────┘    │  ├─ 前端 (Vue)           │     │
│                     │  └─ 内置 Agent × 14       │     │
│                     └──────────┬──────────────┘     │
│                                │                    │
│                     ┌──────────▼──────────────┐     │
│                     │ 浏览器                  │     │
│                     │  ├─ 管理员 (admin)      │     │
│                     │  └─ 普通员工 (viewer)    │     │
│                     └─────────────────────────┘     │
└──────────────────────────────────────────────────────┘
```

所有员工调用的是 **同一个** vLLM 端点；管理员只需在 Settings → 模型管理 里配置一次。

## 2. 内置模型清单（开箱即用）

部署包里已包含 4 条占位内置模型（`config/builtin_models.yaml`），开箱后会自动出现在设置页里，无需新建。

| 模型 ID (`name`) | 用途 | 默认端点 |
|------------------|------|----------|
| `builtin-knowledge-qa` | 知识问答 / 对话 / 智能体主推理 | `http://localhost:8000/v1` |
| `builtin-embedding` | 文档向量化 | `http://localhost:8000/v1` |
| `builtin-rerank` | 检索结果重排序 | `http://localhost:8000/v1` |
| `builtin-doc-parser-vlm` | 扫描件 / 复杂版式解析 | `http://localhost:8000/v1` |

> 默认端点写的是 `localhost:8000`，符合 vLLM 默认端口。客户部署完 vLLM 后直接修改即可，不用重新打包平台。

## 3. 管理员一次性配置流程（约 5 分钟）

### 步骤 1：进入模型管理

- 用 **租户 Owner / Admin** 账号登录
- 顶部头像菜单 → **模型管理**（或左侧导航 → 设置 → 模型管理）
- 普通员工（viewer / contributor）**看不到这个入口**

### 步骤 2：配置 vLLM 端点 + API Key

对每一条内置模型，点 **配置** 按钮：

| 字段 | 填写 | 备注 |
|------|------|------|
| 提供方 (provider) | 选 `vllm` / `openai` / 自建兼容服务 | 列表里任选一个非 "WeKnora Cloud" 的 |
| 模型名称 | 例如 `Qwen2.5-14B-Instruct` | 必须和 vLLM `--served-model-name` 一致 |
| API Base URL | `http://<vllm-host>:8000/v1` | vLLM 默认 OpenAI 兼容路径 |
| API Key | 任意非空字符串 | vLLM 默认不校验，但请求头必须带 |
| 默认模型 | ⭐ 勾选 | 每个类型（KnowledgeQA / Embedding / Rerank）只能有一个默认 |

> 💡 如果客户用的是 OpenAI 官方、Azure、阿里云百炼、DeepSeek 等托管服务，直接在 **新建模型** 里填官方 base URL + key 即可，无需自建 vLLM。

### 步骤 3：设为默认模型

每个模型类型（对话 / 向量 / 重排 / 解析）都必须有且仅有一个默认：

- 进入 模型管理 → 选中对应模型 → 右上角 **"设为默认"** 按钮
- 类型 = KnowledgeQA 的默认模型：所有对话请求 + 内置 Agent 自动使用
- 类型 = Embedding 的默认模型：所有文档入库时使用
- 类型 = Rerank 的默认模型：所有检索结果重排时使用

设置完成后 **立即生效**，无需重启服务。

### 步骤 4：验证普通员工可用性

| 测试项 | 预期结果 |
|--------|----------|
| 普通员工登录后访问 /settings | 看不到「模型管理」入口 |
| 普通员工进入任意会话 | 输入框**没有模型下拉箭头** |
| 普通员工发送消息 | 能正常收到回复（自动用租户默认模型） |
| 普通员工知识库上传文档 | 自动入库（用默认 Embedding 模型） |

## 4. 内置 Agent 的模型选择

### 自动 fallback 机制

所有内置 Agent（`config/builtin_agents.yaml`）的 `model_id` 字段**故意留空**：

```yaml
- id: builtin-doc-review-format
  name: 格式审查智能体
  model_id: ""   # ← 留空 → 运行时自动取「租户默认 KnowledgeQA 模型」
```

含义：
- 客户不写一行代码，平台就自动用上管理员配的默认模型
- 客户如果想让某个 Agent 用特定模型，编辑该 Agent → 把 `model_id` 填成目标模型 ID
- 推荐保持留空——升级内置 Agent 时不会被覆盖

### 内置 Agent 不允许普通员工修改

- 后端路由：`internal/router/routes_agent.go` 已设置 `OwnedAgentOrAdmin` 中间件
- 只有 Agent 的创建者 / 租户 Admin 能编辑
- 普通员工对内置 Agent 是 **只读** 状态（在智能体列表里看不到「编辑 / 删除」按钮）

## 5. 多租户 / 多部门隔离

| 概念 | 含义 | 何时使用 |
|------|------|----------|
| **租户 (Tenant)** | 独立的知识库空间 + Agent 空间 + 成员 + 设置 | 建议每个部门一个租户 |
| **共享 Agent** | 源租户的 Agent 被其它租户「复制 + 订阅」 | 跨部门复用一个已审核的 Agent |
| **跨租户文档共享** | 把文档复制到另一个租户的知识库 | 需要在另一个租户里检索 |

详见 [03-knowledge-base.md §3 跨租户文档共享](./03-knowledge-base.md)。

## 6. 角色矩阵（与平台现状一致）

| 角色 | 能做什么 | 不能做什么 |
|------|----------|------------|
| **Owner** | 全部 Admin 权限 + 删除租户 + 转让 Owner | — |
| **Admin** | 配模型 / 邀请成员 / 编辑内置 Agent / 管理知识库 | 删除租户 |
| **Contributor** | 创建个人 Agent / 上传文档 / 提问 | 改模型 / 删成员 |
| **Viewer** | 提问 / 浏览文档 / 使用已发布 Agent | 改任何配置 |

## 7. 常见问题

### Q1：客户想用 GPU 服务器跑多个模型（对话 + Embedding 不同），怎么办？
A：在内置 4 个模型条目里分别填不同的 base URL / 模型名，分别设默认即可。LuoSA 会在内部按类型路由：
- 对话请求 → KnowledgeQA 默认
- 文档入库 → Embedding 默认
- 检索重排 → Rerank 默认

### Q2：升级平台后内置模型 / Agent 会被重置吗？
A：不会。LuoSA 的「内置」设计是：
- 内置模型 / Agent 在首次启动时**幂等导入**（已存在则跳过）
- 管理员在 Web 端做的修改（API Key、默认标记、端点 URL）持久化在数据库里，升级后保留
- 客户如果想恢复出厂设置：删掉对应记录后重启即可

### Q3：普通员工能自己新建「我的模型」吗？
A：**不能**。这是按客户场景故意收紧的——
- 前端 `settingsAccess.ts` 里 `models: 'admin'`，普通员工看不到模型管理入口
- 后端 `routes_infra.go:14` 的 List/Get 接口对 viewer+ 开放（列出可读），但 Create/Edit/Delete 接口需要 admin+
- 即便前端绕过，后端会拒绝

### Q4：vLLM 端点迁移（IP 变了）需要改哪里？
A：只需在 Settings → 模型管理 → 对应模型 → 编辑 → 改 base URL → 保存。无需重启服务，所有用户立即使用新端点。

## 8. 升级路径建议

| 时间 | 动作 |
|------|------|
| T+0 | 部署 LuoSA + vLLM，按 §3 配置 4 条内置模型 |
| T+1 周 | 导入 `config/workflows/document-review-suite/` 下的 4 个工作流 JSON |
| T+2 周 | 上传第一批历史标书 / 模板到「历史标书库 / 通用模板库」知识库 |
| T+3 周 | 内部试用（建议先给 1 个部门用，再推广） |
| T+4 周 | 收集反馈，调整知识库内容 |

---

> **对接 vLLM 常见问题排查**：如果对话报错 "model not found"，先在 vLLM 端跑 `curl http://<host>:8000/v1/models` 看返回的 `id` 字段，把这个 id 填到 LuoSA 模型配置的「模型名称」字段里即可。
