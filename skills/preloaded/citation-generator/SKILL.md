# Citation Generator

为知识库检索结果生成规范的引用格式。

## 核心能力

1. **来源标注**: 为回答中使用的每个知识点标注来源
2. **格式化引用**: 支持多种引用格式（APA、MLA、Chicago、简化格式）
3. **参考文献列表**: 在回答末尾生成完整的参考文献列表

## 引用格式

### 简化格式（默认）

对于知识库内容，使用以下格式：
```
[文档名称, 第X页/段落X]
```

示例：
```
根据公司政策[员工手册2024.pdf, 第15页]，年假申请需提前...
```

### APA 格式

```
作者. (年份). 标题. 来源.
```

### 参考文献列表格式

在回答末尾，使用以下格式列出所有引用：

```
---
**参考文献**

1. [1] 文档A - 第X章/第Y页
2. [2] 文档B - 第Z段
```

## 使用指南

1. **检索内容时**: 记录每个检索结果的来源信息（文档名、页码、分块ID）
2. **引用时**: 在使用知识点后立即标注来源
3. **汇总时**: 在回答末尾列出完整参考文献

## 注意事项

- 如果检索结果未提供页码，使用分块或段落编号
- 对于同一文档的多次引用，可合并为一条
- 引用应准确对应原文内容，不可虚构来源

## 章节锚点引用格式（合同 / 标书专用扩展）

> 投标审查报告、合同审查报告对每条意见都必须挂源，且源要可点击跳转。
> 除原有"简化格式 / APA / 参考文献列表"外，本 Skill 增加 **章节锚点引用** 体系，
> 用于合同条款、招标文件评分项、法规依据、公司模板等多源场景。

### 章节锚点格式

```
[§<章节编号> <章节标题>, <页码>]
```

**示例**：

```
合同[§3.2 付款方式, 第5页]约定："付款方式为工程验收合格后"。
建议改为：[§3.2 付款方式, 第5页] → 补充"30 日内"明确时限。
依据：《民法典》第 585 条。
```

### 来源类型对照表

| 来源类型 | 引用格式 | 适用场景 |
|---|---|---|
| 普通 KB 文档 | `[文档名, 第X页]` | 通用知识库检索 |
| 合同条款 | `[§<编号> <标题>, 第X页]` | 合同审查报告 |
| 招标文件评分项 | `[§<评分项编号> <评分点>, 招标P<X>]` | 招投标比对报告 |
| 法律 / 行政法规 | `《<法规名>》第X条` | 合规审查依据 |
| 公司内部模板 | `[公司模板 §<编号>]` | 内部规范引用 |
| 历史项目 / 案例 | `[<项目名> <文档类型>, P<X>]` | 经验反馈库 |

### 强制规则

1. **每条审查意见必须挂源**——无源意见会被审查器过滤
   （`wf-doc-review` 的 `builtin-doc-review-synth` 会丢弃 `<no_source>true</no_source>` 的意见）
2. **源格式必须可定位**——`§` + 编号 + 页码三者缺一不可
3. **多源意见用换行分隔**——同一意见引用多个条款时，每个源独立一行
4. **下划线占位区分**：`[§?_?_?]` 表示"章节编号待人工补"，提醒读者不要引用
5. **跨文档引用顺序**：法规 > 公司模板 > 合同原文 > 经验反馈，按权威性从高到低

### 与 office-template-fill 的衔接

`office-template-fill/scripts/insert_track_changes.py` 接受审查意见时，会用 `anchor.section`（即 `§3.2 付款方式` 去掉 `§` 前缀的部分）匹配 docx 里的标题。
所以本 Skill 输出的章节锚点必须与 docx 实际标题完全一致，否则锚点会失败。
